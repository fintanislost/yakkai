# Arona Scene Rendering — Situation Report

## Scene: Sleeping Arona (Workshop 3228578419)

### What it is
A Blue Archive puppet scene with a 14-bone skinned crop-sheet character, background layers (desk, wall, chair), lens flare effects, sparkle particles, and Z sleep letters.

### Scene type: Puppet
Detected by `has_puppet_objects` flag (image objects with non-empty `.puppet` field).

### What works
- Character renders via direct puppet mesh with SKINNING (no effect chain)
- Background layers render with raw textures (effects stripped)
- Flare/lens layers render through their full effect chain (HLSL UV fix active)
- Hex-hash named layers (auto-generated WE flare components) keep their effects
- Sparkle particles and Z letters render normally
- Safe non-channelmap puppet effect chains render atlas-first, then publish through a puppet-skinned final mesh so water/pulse/LUT/shake motion stays in WE crop-sheet space before skinning.
- Debug manifests record preserved protected crop-sheet captures normally when their visible effects are limited to recognized water/LUT/pulse/shake families; stripped protected crop-sheet chains still go into `protectedPuppetDiagnostics`
- Harness-only protected puppet probes can still force or prefix-slice layer `405` (`ARONA_CROP_SHEET`) with `--debug-effect-captures --debug-effect-probe-layers 405`, then summarize it with `tools/arona_protected_puppet_lab.py`. Add `--debug-effect-capture-delay-ms <ms>` when inspecting a delayed screenshot or sequence frame so time-dependent ribbon/LUT TGAs line up with the visual evidence. When passed a normal comparator run through `--normal-summary`, the lab also reports capture statistics, stage-boundary comparisons, route diagnostics, final-publish composition diagnostics, probe-final-to-normal drift, and screen-space centroid drift. Forced probe frames remain diagnostic artifacts. `--debug-puppet-effect-route-only` keeps the puppet offscreen/final-display route active with zero visible effects so route/composition failures can be separated from shader failures.

### What doesn't work (known limitations)
- Background LUT color grading effects — regular image-layer `lut-only` chains can render. Protected puppet crop-sheet water/LUT/pulse/shake chains can render through the repaired generic route, but protected blur/color-grade and unknown mixed chains remain stripped.
- Background blur effects — produce washed-out or broken output through the full pipeline. Stripped.
- Arbitrary puppet mesh through effect chain — safe water/pulse/LUT/shake chains use the atlas-first deferred puppet-final route; unsupported mixed puppet chains remain stripped until they have focused pass-boundary evidence.
- Script execution — WE scripts are partially evaluated for simple color/alpha/origin/visible bindings. Unsupported script patterns may still differ from Wallpaper Engine.

**Rules:**
1. This block ONLY runs for Puppet scene type
2. Flare layers (name contains "flare", "lense", "lens") KEEP their effects
3. Hex-hash layers (16+ hex chars) KEEP their effects
4. Regular image-layer `lut-only` chains can keep effects
5. ALL other nonessential layers get effects stripped
6. The puppet layer itself also gets effects stripped (separate check: `if (puppet && hasEffect)`)
7. Flare/lens/hash layers keep their authored or script-resolved alpha. Zero-alpha flares stay hidden instead of being forced visible.
8. Protected crop-sheet diagnostics are metadata-only only when the chain is still stripped. Safe protected water/LUT/pulse/shake chains now create normal capture records and write through the repaired final-publish route.
9. Layer `405` forced probe captures are harness artifacts. A probe run writes effect-input/effect-output/default/final-publish captures for analysis, but probe-only variants and prefix slices are not normal output.
10. The protected puppet lab classifies `effect-input->effect-output`, `effect-output->final-publish`, and `default-before-effect->default-after-effect` boundaries from capture images. Treat `local-to-frame-composition` as a routing/composition clue, not proof of an alpha bug by itself.

### Regression history
This scene has broken repeatedly during development. Common failure modes:

1. **Washed-out blue background** — caused by LUT/blur effects running through the pipeline. Fix: strip effects for non-flare layers.
2. **Black diamond overlay** — `c7884e...` hex-hash layer rendering with opaque black background. Fix: keep its effect chain (it's a lens flare component).
3. **White rectangle** — flare layer with wrong blend mode. Fix: keep effect chain for proper alpha processing.
4. **Invisible flares** — flare textures can be controlled by script-resolved alpha. Older debug builds forced `alpha=1.0`, which made Night-only disabled flares appear. Current behavior keeps flare effect chains but preserves authored/script-resolved alpha. The shader cache can mask this path — always verify with a fresh cache (`rm -rf ~/.cache/wescene-renderer/3228578419/spvs01/`).
5. **Puppet mesh tile seams** — background pulse effects create brightness variations visible through puppet mesh gaps. Fix: strip background effects.
6. **Missing desk/background** — global effect changes (like HLSL define in fragment shaders) affecting lighting normals. Fix: HLSL only in common header, let each shader handle its own fragment HLSL blocks.
7. **Protected chain probe drift** — forcing `ARONA_CROP_SHEET` layer `405` through `--debug-effect-probe-layers 405` produces usable diagnostic captures but materially changes final-frame comparison metrics. Keep this as lab evidence, not a normal policy change.
