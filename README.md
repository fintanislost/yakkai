# Paper Gradient

`Paper Gradient` is a KDE Plasma 6 wallpaper plugin focused on a small set of high-value background modes. The current version supports configurable gradients, local video playback, Wallpaper Engine video and web modes, a split safe/native scene workflow, and a repo-owned native scene backend that can be staged into the wallpaper package for guarded scene debugging.

## Current scope

- Plasma 6 wallpaper package under `wallpapers/io.papercompany.gradient`
- Top-level content selector for gradient or local video
- Two configurable colors
- Preset picker for common palette and motion combinations
- Adjustable gradient angle
- Optional slow animation
- Adjustable drift amount
- Optional vignette for edge darkening
- Optional time-of-day mode with separate day and night palettes
- Explicit mode selector so manual and time-of-day editing stay separate
- Local video file playback through `QtMultimedia`
- Wallpaper Engine video-project scanning from a Steam library
- Wallpaper Engine web-project scanning from a Steam library
- Wallpaper Engine scene-project scanning and safe placeholder selection from a Steam library
- Split `Wallpaper Engine Scene` and `Wallpaper Engine Scene Native` content modes
- Video sizing controls for crop, fit, and stretch
- Audio mute control for media modes
- Persistent settings through Plasma wallpaper configuration
- Native CMake workspace for a repo-owned scene backend and standalone harness
- Generated `contents/imports/` staging for the repo-owned native scene module

`wallpapers/io.papercompany.gradient/metadata.json` must declare both `ServiceTypes: ["Plasma/Wallpaper"]` and `X-Plasma-MainScript: "ui/main.qml"`. Plasma rejects the package as invalid before any QML or backend code loads if either package entry is missing.

Sleeping Arona currently has a scene-specific display fallback for `ARONA_CROP_SHEET`: when its authored local effect chain is disabled for stability, the native backend now renders that source on a flat card instead of the coarse skinned puppet mesh. This is a pragmatic “display better” fallback, not a claim of full Wallpaper Engine fidelity.

## Install

Install the wallpaper package for the current user:

```bash
kpackagetool6 -t Plasma/Wallpaper -i wallpapers/io.papercompany.gradient
```

After installation, open the Plasma wallpaper picker and choose `Paper Gradient` from the wallpaper type list.

## Update during development

```bash
kpackagetool6 -t Plasma/Wallpaper -u wallpapers/io.papercompany.gradient
```

For `Wallpaper Engine Scene Native`, build the native workspace first so the repo-owned `io.papercompany.scene` module is staged into `contents/imports/` before you update the wallpaper package:

```bash
cmake -S . -B build
cmake --build build
kpackagetool6 -t Plasma/Wallpaper -u wallpapers/io.papercompany.gradient
```

## Remove

```bash
kpackagetool6 -t Plasma/Wallpaper -r io.papercompany.gradient
```

## Quick validation

For the Plasma package, the fastest checks are:

```bash
qmllint wallpapers/io.papercompany.gradient/contents/ui/main.qml
qmllint wallpapers/io.papercompany.gradient/contents/ui/GradientBackground.qml
qmllint wallpapers/io.papercompany.gradient/contents/ui/VideoBackground.qml
qmllint wallpapers/io.papercompany.gradient/contents/ui/WebBackground.qml
qmllint wallpapers/io.papercompany.gradient/contents/ui/config.qml
```

For a package-structure smoke test without writing into your user Plasma directory, install into a fresh temporary package root:

```bash
tmp_root="$(mktemp -d)"
kpackagetool6 -t Plasma/Wallpaper -i "$(pwd)/wallpapers/io.papercompany.gradient" -p "$tmp_root"
```

For the native workspace, configure a separate build tree:

```bash
cmake -S . -B build
cmake --build build
```

The repo-owned scene backend is enabled by default through `PAPER_ENABLE_VENDORED_SCENE_BACKEND=ON`. To force the fallback stub module instead, configure with:

```bash
cmake -S . -B build -DPAPER_ENABLE_VENDORED_SCENE_BACKEND=OFF
```

When the native backend target builds, it copies the repo-owned `io.papercompany.scene` module into `wallpapers/io.papercompany.gradient/contents/imports/io/papercompany/scene/` so `Wallpaper Engine Scene Native` can load it through a local QML import.

The repo-owned native scene backend is still partial. It fully supports the existing image/particle/sound/light path and now includes an experimental static fallback for Wallpaper Engine `model` scene objects. That fallback accepts both the older skinned MDL layouts and the 56-byte static vertex layout used by assets such as Arsenal's `pistols.mdl`, parses multiple static submesh sections when the MDL contains them, preserves accumulated color output when those submeshes render as separate passes, but now only after the first write has established a defined render-target clear instead of forcing `_rt_default` to load undefined contents on the first model pass. Those first opaque model passes also keep the cleared alpha channel instead of overwriting it with diffuse-texture alpha, because these model diffuse sidecars often store non-opacity data there. The same first-write clear rule now also treats intermediate effect render targets as transparent instead of clearing them to the scene background color, which prevents sparse alpha image-effect layers such as Blue Archive curtains and foliage from turning into pale rectangular quads before their effect shaders sample them. It prefers the first keyframe from a Wallpaper Engine camera-path script when one is declared for the scene, now honors the authored camera `up` vector instead of dropping camera roll, and now also carries that rotated camera-node `up` vector through the actual perspective view-matrix build instead of silently falling back to world-up inside `SceneCamera`. That same perspective `LookAt(...)` path now also builds the inverse camera view transform instead of the forward camera transform, which fixes rotated perspective model scenes like Arsenal that were previously being pushed behind the clip plane and rendering black. It keeps the scene-authored/default perspective FOV during fill-mode updates instead of recomputing it from the orthographic camera height, and now also advances declared Wallpaper Engine camera-path segments at runtime by interpolating between their authored transforms instead of freezing model scenes at the first keyframe forever. The scene-graph node setters now also invalidate cached transforms when that animated perspective camera moves, so the live view matrix follows the updated camera pose. For 2D scene parallax, the shader-value updater now treats authored `parallaxDepth` as a mouse-relative offset instead of baking in a permanent translation from the node's absolute authored position, which brings parallax-sensitive scenes like Blue Archive Yuuka much closer to their authored center in the Plasma runtime. The parser also now materializes bare transform/group objects that have no drawable payload of their own, even when they omit `solid: true`, so child layers no longer get dropped when scenes like Sleeping Arona parent their foreground, desk, wall, chair, and sky layers under pure transform anchors. Sleeping Arona also exposed a separate puppet-MDLA compatibility gap: some `MDLA0005` files insert large per-animation trailers between headers, so the parser now rescans for the next structurally valid animation header instead of assuming those headers are contiguous or only separated by the older tiny trailer blocks. That same scene also uses a companion `*_channelmap.json` material for its crop-sheet puppet prepass, so the native parser now recognizes that sidecar, promotes the prepass to the authored `puppettexturechannels` shader, keeps that specific prepass on the authored unskinned packed-UV mesh instead of forcing it through the native `SKINNING` combo, and now also decodes the packed channel-map UV payload as unsigned normalized image coordinates instead of signed normalized data. The resulting crop-sheet prepass is then routed through the authored image-effect ping-pong chain on a flat image card, rather than remapping the effected result back through puppet geometry a second time. The Vulkan shader compiler now also forwards each real shader stage into `glslang` parsing instead of registering every unit as vertex-stage input, which fixes authored fragment shaders like `puppettexturechannels` that legitimately use `discard` or `gl_FragColor`-style fragment behavior. The fallback chooses among camera-scored proper axis-basis remaps for static MDL fallback instead of relying on a single guarded Y-axis flip. That basis chooser is now also submesh-aware enough to penalize candidates that pull a huge thin backdrop quad in front of the dense model body, and when the fallback sees that same large thin low-vertex backdrop pattern alongside denser submeshes it now excludes that backdrop from basis/framing heuristics without dropping it from the final render, while also drawing those backdrop submeshes first so they stay behind the denser weapon geometry. The selected basis remap is applied directly to static vertex positions, normals, and tangents before the authored model transform, the static fallback can also apply a small camera-plane reframe when the selected model still lands visibly off-center under the authored scene camera, and its follow-up auto-fit now measures the actual projected model extent under the authored perspective camera instead of relying on the older coarse radius-based shrink heuristic. The model fallback now also seeds the image-shader defaults that static materials expect, including `g_Brightness=1`, `g_UserAlpha=1`, and `g_Color4=(1,1,1,1)`, so `genericimage2` and the simpler `generic` path do not start from black output. The renderer also now allocates, populates, and binds every reflected uniform buffer block for a pass instead of only the first one, which matters for Wallpaper Engine shaders like `genericimage2` whose vertex and fragment uniforms land in separate reflected blocks, and it now clamps uniform uploads to the reflected member size instead of blindly overrunning UBO storage when an authored array payload is larger than the compiled block member. Static fallback materials that already use Wallpaper Engine's authored `generic` shader now stay on that path even when they depend on `lightmap` or `normalmap` combos, while still disabling `reflection` because the fallback does not build reflection render targets yet. Non-`generic` fallback materials still use the simpler diffuse-only image path, which can prefer standard raster sidecars such as `.tga` or `.png` when a model material ships them alongside `.tex`, and that diffuse-only path forces opaque blending instead of inheriting Wallpaper Engine's default translucent material state because many of these diffuse alpha channels encode non-opacity data. For script-heavy scenes that embed Wallpaper Engine media-integration UI, the parser now also suppresses those unsupported utility layers by default instead of rendering their raw fallback card values as oversized quads, and authored child layers no longer fall back to the root scene graph when their scripted parent container never materializes. Lighting, full material fidelity, full user-property/shared-script execution, and fuller camera-path semantics are still incomplete.

The standalone scene harness can then be run outside Plasma:

```bash
./build/native/scene_harness/paper_scene_harness \
  --backend system \
  --source /absolute/path/to/scene.json \
  --assets /absolute/path/to/wallpaper_engine/assets \
  --fill crop
```

For targeted scene-debugging in Plasma, the native backend can now also dump specific intermediate render targets to `/tmp/papercompany-debug/` during a live run. The current debug wiring is focused on Sleeping Arona's `ARONA_CROP_SHEET` path and writes:

- `arona-source-puppet.tga`
- `arona-last-effect.tga`
- `arona-final-default.tga`

## Reference materials

- `qt-qml-module/`: the installed compiled QML module manifest

This reference is intentionally partial. It focuses on backend loading, pause policy, and the custom QML module rather than the full Workshop browser UI.

`fixes.md` records the concrete issues and debugging fixes that got the current video and Wallpaper Engine paths working in practice.

`native/scene_backend` now builds a repo-owned `io.papercompany.scene` module against vendored native scene sources under `vendor/upstream_debug/`, including a fully vendored `glslang` build. That backend now reaches Vulkan/GL init, scene parsing, render-graph compilation, first draw, successful external-texture import, active per-image external semaphore handoff in the standalone harness, and staged loading through `Wallpaper Engine Scene Native`. The previously suspicious `GL_INVALID_ENUM` signal is now tracked as stale GL state before the next sync point, not a confirmed `glImportMemoryFdEXT` failure. The repo-owned backend still remains experimental, and model-based Wallpaper Engine scenes currently use a limited diffuse-only fallback rather than full material/lighting support. That fallback now also covers the 56-byte static MDL vertex layout seen in some default Wallpaper Engine projects and preserves earlier submesh color output when a model expands into multiple render passes. `native/scene_harness` is the standalone debugging app for scene work outside `plasmashell`.

## Configuration keys

- `StartColor`: gradient start color
- `EndColor`: gradient end color
- `Angle`: base gradient angle in degrees
- `Animate`: enables slow angle drift
- `AnimationDuration`: full animation cycle length in seconds
- `DriftDegrees`: maximum angular drift applied during animation
- `VignetteStrength`: edge darkening amount from `0` to `60`
- `UseTimeOfDay`: enables local-time blending between day and night palettes
- `DayStartHour`: hour when blending into the day palette begins
- `NightStartHour`: hour when blending into the night palette begins
- `TransitionMinutes`: blend duration at each schedule boundary
- `DayStartColor`: first color used for the day palette
- `DayEndColor`: second color used for the day palette
- `NightStartColor`: first color used for the night palette
- `NightEndColor`: second color used for the night palette
- `ContentMode`: selects `Gradient`, `Video`, `Wallpaper Engine Video`, `Wallpaper Engine Web`, `Wallpaper Engine Scene`, or `Wallpaper Engine Scene Native`
- `VideoSource`: local video file path
- `VideoFillMode`: `Crop`, `Fit`, or `Stretch`
- `VideoMuted`: mutes wallpaper audio
- `WEVideoLibraryPath`: shared Steam library root used for Wallpaper Engine scanning
- `WEVideoProjectPath`: selected Wallpaper Engine `project.json` path
- `WEVideoProjectTitle`: selected Wallpaper Engine project title
- `WEVideoSource`: resolved local video file for the selected Wallpaper Engine project
- `WEWebProjectPath`: selected Wallpaper Engine web `project.json` path
- `WEWebProjectTitle`: selected Wallpaper Engine web project title
- `WEWebSource`: resolved local entry HTML file for the selected Wallpaper Engine web project
- `WEWebPropertiesJson`: serialized default Wallpaper Engine user properties for the selected web project
- `WESceneProjectPath`: selected Wallpaper Engine scene `project.json` path
- `WESceneProjectTitle`: selected Wallpaper Engine scene project title
- `WESceneSource`: resolved local scene source for the selected Wallpaper Engine scene project
- `WESceneSourceKind`: the resolved scene source filename, such as `scene.pkg` or `scene.json`
- `WEScenePropertiesJson`: serialized default Wallpaper Engine user properties for the selected scene project. If this config value is empty at runtime, the native scene backend now falls back to the scene's adjacent `project.json`.
- Scene-property and animation wrapper objects now unwrap their authored `.value` payload for transform arrays and numeric booleans during parsing. That improves compatibility for Blue Archive scenes that drive placement and visibility through scripted wrapper objects instead of plain scalars.
- The native scene fallback currently forces `loadingintro=false` when activating scene property defaults. That avoids getting stuck on one-shot startup overlays in scenes whose intro dismissal depends on runtime script behavior the native backend does not implement yet.
- The native scene fallback also scans scene scripts for startup `getAnimationLayer(...).pause()` calls and applies those puppet-layer pause defaults during parsing. That keeps script-paused Blue Archive puppet layers from free-running just because the native backend does not execute the original helper script.
- Sleeping Arona-style crop-sheet puppets can also ship a companion `*_channelmap.json` prepass material. The native parser still supports that `puppettexturechannels` route when the source material explicitly requests it, feeding the prepass with a dedicated packed-UV puppet mesh, decoding its packed channel-map UVs as unsigned normalized image coordinates, and seeding `g_BlendMap` from the bones that actually change in the currently visible puppet animation layers instead of a global fallback.
- That companion-channelmap path is explicit-material-driven again. The native backend no longer promotes a sibling `*_channelmap.json` sidecar just because it exists next to a `genericimage4` puppet asset; ordinary puppet materials stay on the ordinary puppet/effect pipeline unless the source material itself requests the special prepass route.
- Sleeping Arona currently also has a scene-specific safety fallback on top of that. `ARONA_CROP_SHEET` now bypasses its local authored card-effect chain entirely and renders as a plain puppet image when the native backend determines that the broader puppet-plus-effects composition route is still producing unusable output. This is a pragmatic display fallback, not a claim that the authored Wallpaper Engine composition has been fully reproduced.
- Sleeping Arona now also suppresses its separate `Adjustable Composition Layer` utility image in native fallback. That object is a visible `models/util/composelayer.json` strip parented under the background art, and in practice it was dominating the scene with a broad duplicated sky/card overlay instead of acting like a subtle finishing pass.
- Sleeping Arona's ordinary `genericimage4` puppet-with-effects path is now pinned to the upstream composition model instead of the newer native standalone-display experiment. The source material renders on the authored flat card, the parser appends a synthetic puppet `genericimage4` stage as the last effect node, and `SceneImageEffectLayer` publishes that last stage back with the puppet mesh the same way upstream does.
- That Sleeping Arona channel-map seeding now keeps startup-paused puppet layers eligible for the frame-0 overlay pose as long as they are still visible. That matches Wallpaper Engine's `pause()` behavior more closely: the layer should stop advancing, not disappear from the rendered channel-map state.
- For those same channel-map puppets, the Sleeping Arona path now keeps `puppettexturechannels` on an authored unskinned prepass mesh whose flat-card positions come from the original crop-sheet UVs instead of the skinned puppet pose. That keeps the entire offscreen effect chain in the same UV space as `ARONA_CROP_SHEET`, so the final standalone `genericimage4` display stage can return to the authored puppet UV mesh instead of depending on a separate image-space UV remap.
- The loader still has a defensive `puppettexturechannels` skinning injection available if a material really does resolve `SKINNING`, and that helper is now keyed off resolved combo state and no longer depends on one exact source-line layout.
- After that unskinned channel-map prepass, the Sleeping Arona route now keeps the authored card effects offscreen on the preprocessed crop-sheet atlas and then samples the last authored effect render target from a separate final `genericimage4` puppet node in the main scene. That avoids republishing the same skinned `genericimage4` effect node twice while still matching the packaged `channel-map prepass -> card effects -> final puppet display` structure, and the final overlay stage now masks its output with both the authored `ARONA_CROP_SHEET_channelmap` alpha and the original crop-sheet alpha instead of trusting the broad offscreen effect RT alpha by itself.
- That final Sleeping Arona overlay is now also restricted to puppet triangles where the active channel-map slot set meaningfully owns most of the corners, instead of treating a triangle as overlay-owned merely because those slots appear as the primary index or contribute only a tiny mixed weight. The untouched crop-sheet body stays on the separate base `genericimage4` display node, while the offscreen channel-map/effect result is only sampled back onto the genuinely animated overlay region instead of broad body-sized triangles that only weakly reference the same slot.
- The separate Sleeping Arona base `genericimage4` display now keeps the full authored puppet mesh even while the channel-map overlay path is active, but it no longer relies on coarse geometry subtraction to hide the overlay-owned region. Instead it uses an inverse channel-map alpha mask in the fragment shader, which suppresses the animated overlay area per-pixel without introducing the large complement polygons that the geometry-only split produced.
- The filtered Sleeping Arona overlay now also samples the offscreen channel-map/effect result on an image-space mesh for just that weighted active region, instead of routing the same subset back through the full authored puppet UV mesh. That keeps the final overlay in the same flat crop-sheet space as the offscreen effect chain while the untouched body stays on the separate puppet display node.
- That filtered image-space overlay builder also had a remap-table sentinel bug: its per-vertex remap array was initialized with `uint32_t::max()` but one of the filtered image-space paths still checked for `uint16_t::max()`, so the overlay subset always looked invalid and silently fell back to the broad authored puppet UV mesh. The sentinel check now matches the actual `uint32_t` remap table, so the weighted image-space overlay route can engage for Sleeping Arona instead of immediately bailing out.
- The standalone Sleeping Arona base and overlay display nodes now avoid both transform failure modes in the special crop-sheet path. They no longer copy the full crop-sheet transform a second time when the source image node still carries the authored placement, and when the offscreen effect setup resets `spImgNode` to identity they now reuse a saved copy of the pre-effect image transform explicitly. That keeps those standalone display nodes on the authored world transform without double-applying translate/scale/rotation/alignment.
- The Sleeping Arona crop-sheet path still has a zero-slot fallback for scenes that truly have no visible channel-map-driven puppet layers, but a startup-paused visible layer like `Arona Drool` no longer triggers that branch by itself. In practice that keeps the authored channel-map/effect route alive for the paused frame-0 pose instead of collapsing immediately to the plain puppet base.
- Effect-stage puppet materials now also publish their authored `SKINNING`/`BONECOUNT` combos before shader preprocessing instead of after it. That lets synthetic puppet stages in image-effect chains compile with the correct skinned shader path instead of silently behaving like unskinned card passes on the puppet mesh.
- Image-effect outputs now also preserve the original image node's parent hierarchy when the final effected card is returned to the main scene. That matters for Sleeping Arona-style layers whose final effect result would otherwise keep only the source node's local transform and lose the authored parent/world placement.
- Multi-effect image layers now also only publish the last authored effect stage back to the main scene. Intermediate `pulse`/`waterwaves`/`shake` passes stay in the ping-pong chain instead of each being redirected to the main render target as if they were separate final layers.
- The native texture loader now also emits targeted diagnostics for Sleeping Arona's `ARONA_CROP_SHEET` and `ARONA_CROP_SHEET_channelmap` textures, including parsed format, dimensions, and basic per-channel coverage stats. That is currently used to distinguish a bad prepass/effect contract from a bad source texture decode without having to guess from screenshots alone.
- `WESceneExperimentalEnabled`: compatibility mirror for the `Wallpaper Engine Scene Native` content mode
- `WESceneMouseInput`: enables direct scene mouse and hover input for the experimental scene runtime

## Content modes

The settings panel now starts with a top-level `Content` selector:

- `Gradient`: keeps the original Paper Gradient renderer
- `Video`: plays a local video file through `QtMultimedia`
- `Wallpaper Engine Video`: scans a Steam library for Wallpaper Engine `video` projects and reuses the same `QtMultimedia` playback path
- `Wallpaper Engine Web`: scans a Steam library for Wallpaper Engine `web` projects and loads their local HTML entrypoints through `QtWebEngine`
- `Wallpaper Engine Scene`: scans a Steam library for Wallpaper Engine `scene` projects and stays on the safe diagnostics placeholder
- `Wallpaper Engine Scene Native`: reuses the same scene selection flow, but routes into the guarded experimental repo-owned `io.papercompany.scene` renderer staged under `contents/imports/`

## Time-of-day mode

When `Content` is set to `Gradient`, the settings panel exposes a `Mode` selector:

- `Manual gradient`: edit a single two-color gradient for the whole day
- `Time of day`: edit separate day and night palettes plus the transition schedule

In `Time of day`, the wallpaper ignores the manual start and end colors and instead blends between the configured day and night palettes according to the local system time. The first transition starts at `DayStartHour`, the second starts at `NightStartHour`, and each transition lasts `TransitionMinutes`.

## Media modes

`Video` mode is intentionally narrow in the first implementation:

- local file only
- `QtMultimedia` backend only
- infinite loop playback
- file selected through the wallpaper settings picker
- mute toggle
- crop, fit, and stretch sizing

Actual playback support depends on the multimedia codecs installed in the current Plasma system or VM. If a file installs correctly but does not render, test a different container or codec before assuming the wallpaper package is broken.

`Wallpaper Engine Video` mode is also intentionally narrow:

- Steam library picker in the settings page
- scans only Wallpaper Engine projects whose `project.json` type is `video`
- resolves the actual media file during settings-time and saves it into the wallpaper config
- reuses the same `QtMultimedia` runtime backend as local video mode
- does not support Wallpaper Engine `scene` projects yet

`Wallpaper Engine Web` mode is the first-pass web path:

- shares the same Steam library picker and scan helper as Wallpaper Engine video mode
- scans only Wallpaper Engine projects whose `project.json` type is `web`
- loads the resolved local HTML entry file through `QtWebEngine`
- injects a direct JavaScript compatibility shim for `window.wpeQml`, `window.wallpaperPropertyListener`, and `window.wallpaperRegisterAudioListener(...)` instead of depending on a live `QWebChannel` bootstrap
- does not yet emulate the full Wallpaper Engine audio, media-integration, or per-project settings stack
- explicitly enables `QtWebEngine` WebGL and accelerated 2D canvas support, though some VM GPU stacks may still report WebGL as unavailable

The settings-side scan uses the bundled `contents/tools/we_video_scan.py` helper, so the Plasma system running the settings UI needs `python3` available. The web mode requires `QtWebEngine` in the Plasma session.

`Wallpaper Engine Scene` mode is now the stable research and diagnostics path:

- shares the same Steam library picker and scan helper as the other Wallpaper Engine modes
- scans only Wallpaper Engine projects whose `project.json` type is `scene`
- resolves the real on-disk scene source conservatively, preferring an existing `scene.pkg` or `scene.json` instead of trusting metadata alone
- stores the selected project and source path in the wallpaper config
- shows placeholder diagnostics for source kind, source existence, Wallpaper Engine assets-path existence, and repo-owned native module staging status
- keeps the placeholder active and does not try to start the native scene backend

`Wallpaper Engine Scene Native` mode is the guarded backend workbench:

- reuses the same Steam library picker, scan helper, and saved scene selection as `Wallpaper Engine Scene`
- routes the selected scene through the guarded repo-owned `io.papercompany.scene` path staged under `contents/imports/`
- reuses the existing sizing and mute controls when the experimental scene renderer is enabled
- keeps direct scene mouse and hover input off by default, with an explicit opt-in toggle for testing parallax-sensitive scenes
- routes that experimental attempt through a guard component that falls back to the placeholder if the scene runtime fails to load cleanly
- restarts the guarded experimental scene runtime when the selected scene source, asset root, fill mode, or mouse-input settings change, so scene swaps do not mutate a live native backend instance
- logs scene guard, source, fill-mode, mouse-input, first-frame state, geometry, DPR, and Qt Quick graphics API details through the existing `[Paper Gradient]` journal prefix, while the high-frequency native render/semaphore logs are rate-limited to keep live runs readable

The safe mode exists to preserve stable selection and diagnostics. The native mode exists to isolate backend debugging from that safe path.

Current limitation from host-side validation:
- the guarded QML path now launches scenes cleanly, restarts on scene-selection and runtime-setting changes, and matches the native swapchain size, but some scenes still render offset because the repo-owned native backend continues to hit stale `GL_INVALID_ENUM` state around its external-texture path

If the video backend itself cannot initialize in the current Plasma session, Paper Gradient now keeps the wallpaper selected and shows an in-wallpaper error message instead of silently falling back to another content path.

If the web backend cannot initialize in the current Plasma session, Paper Gradient keeps the wallpaper selected and shows an in-wallpaper error message instead of silently falling back to another content path.

If a selected video still renders as black, the wallpaper keeps a small status overlay visible until the first decoded frame arrives. That overlay now distinguishes loading, missing video tracks, stalled playback, and cases where playback time advances without any frames reaching the wallpaper.

For Wallpaper Engine web mode, the on-wallpaper status overlay is now limited to actual page-load problems. If the page is already rendering, Wallpaper Engine bridge or property-payload timing issues are logged instead of being shown on screen.

For runtime diagnostics from a live Plasma session, the wallpaper now emits QML logs with a `"[Paper Gradient]"` prefix. In the VM, the simplest way to watch them is:

```bash
journalctl --user -f | rg "Paper Gradient"
```

Those logs include the resolved video source, loader status, `MediaPlayer` state transitions, `hasVideo`, playback position, and frame-delivery events.

For Wallpaper Engine web debugging, the same `"[Paper Gradient]"` log prefix now also includes `QtWebEngine` console messages emitted by the loaded page.

## Preset helper

The wallpaper settings panel includes a preset picker that seeds the current controls with a ready-made palette and motion profile. It is a quick-fill helper, not a locked mode, so you can choose a preset and then keep tweaking the individual fields.

## Wallpaper Engine research notes

Wallpaper Engine integration is split by source type:

- `video`: feasible with a small scan helper plus the existing `QtMultimedia` backend
- `web`: feasible with `QtWebEngine`, `QtWebChannel`, and a lightweight compatibility bridge
- `scene`: scan-and-select support exists, and native renderer experiments now live in a separate content mode that still depends on compiled `SceneViewer` types and a larger native runtime

The closest working reference remains the third-party `Wallpaper Engine for Kde` plugin under `references/wallpaper-engine-kde`.
